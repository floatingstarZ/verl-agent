\section*{Review 结论}
当前 StepPPO-v3 的设计应保持非常简单：它就是 GiGPO 训练上的 value head 实验。目标不是提出新的 advantage 或新的 PPO ratio，而是看 value head 能不能稳定学出来，并且确认加了这个 head 不影响 GiGPO 的训练。

因此，v3 的正确默认定义是：
\begin{lstlisting}
StepPPO-v3 = GiGPO policy training + actor-side shared value head
\end{lstlisting}

主线不应再被描述成 ``先验证 value head，后面再做完整 v3''。当前这个 value-head-only 设定本身就是 v3。

\section*{必须坚持的边界}
\begin{itemize}
  \item GiGPO policy advantage 不变。
  \item GiGPO policy loss 路径不变。
  \item value head 使用和 StepPPO-v2 同一类 actor-side shared value head 思路。
  \item value head 学 step-level return/value target。
  \item 主线默认 \path{detach_value_backbone=true}，避免 value loss 干扰 actor backbone。
  \item success criterion 是 value 学得稳且 GiGPO 不退化。
\end{itemize}

\section*{当前脚本}
主线脚本应是：
\begin{lstlisting}
exps/run_webshop_step_ppo_v3_value_head_4gpu_paper_align_simple.sh
\end{lstlisting}

它应继续调用 GiGPO-v1 value-aux 路径，而不是切到一个新的 \path{step_ppo_v3} estimator。

\section*{Review 关注点}
\subsection*{1. value head 是否稳定}
必须看：
\begin{lstlisting}
actor/value_loss
actor/value_rmse
actor/value_mae
actor/value_explained_variance
actor/value_pred_std
actor/value_return_std
\end{lstlisting}

如果 value loss 看似下降，但 explained variance 长期小于等于 0，说明 value head 没有学到有用 signal。

\subsection*{2. 是否影响 GiGPO 训练}
必须和 no-value-head GiGPO baseline 对比：
\begin{lstlisting}
episode/valid_action_ratio
response_length/mean
response_length/clip_ratio
actor/pg_loss
actor/grad_norm
val/success_rate
val/webshop_task_score (not success_rate)
\end{lstlisting}

如果这些指标明显变差，哪怕 value head 指标变好，当前 v3 也不能算成功。

\subsection*{3. detach 对照}
主线应是 detach=true。detach=false 只作为风险复验，用来确认 shared-backbone value regression 是否会干扰 policy。它不应该成为默认主线。

\section*{不要扩大 v3 范围}
以下内容不要写进当前 v3 默认设计：
\begin{itemize}
  \item \path{algorithm.adv_estimator=step_ppo_v3}；
  \item pure step advantage；
  \item action-level PPO ratio；
  \item sequence geometric ratio；
  \item separate critic；
  \item 复杂 reward 重写；
  \item 默认让 value loss 回传 actor backbone。
\end{itemize}

这些都可能是未来新版本或额外 ablation，但不是当前 v3。

\section*{通过标准}
当前 v3 通过的标准很直接：
\begin{enumerate}
  \item value head 的 RMSE/MAE 稳定，explained variance 出现正向 signal；
  \item value prediction 不塌缩成常数，\path{actor/value_pred_std} 保持合理；
  \item GiGPO 的 valid action、response length、clip ratio、validation score 不因为 value head 明显退化；
  \item detach=true 明显比 detach=false 更不干扰 policy，或者至少不比 no-value-head baseline 差。
\end{enumerate}

\section*{最终意见}
当前设计应去掉所有不必要复杂度。v3 就是 value head；看它能不能学，且不影响 GiGPO。AGENTS 中也应强制记录这一点，避免后续 agent 又把 v3 扩展成 action-level PPO 或新的 advantage 算法。
